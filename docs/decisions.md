# Decisions

| # | Kind | Decision | Why | Alternatives considered | Consequence |
|---|---|---|---|---|---|
| 1 | product | Build an own web reader with a library page. Decided 2026-10-24. | Vendor e-reader apps have no public API to add books. | Convert, then email the file to a vendor device address. Rejected: the vendor controls delivery, so the app cannot measure `book_ready`. | The app owns upload, storage and the reader. |
| 2 | product | Metric (assumed): 95% of uploads are readable in the library within 2 minutes. Decided 2026-10-24. | No real data exists yet. The events `upload_received` and `book_ready` make it countable. | Count uploads only. Rejected: a count shows nothing about readable books. | The app records both events with timestamps. |
| 3 | product | User (assumed): a reader with DRM-free EPUB and PDF files. Decided 2026-10-24. | The input names one e-reader brand only. DRM files cannot convert legally. | All e-reader owners, DRM files included. Rejected: DRM removal has legal risk. | DRM files are rejected with a reason. |
| 4 | product | Accept EPUB and PDF only. Normalise EPUB. Keep PDF as it is. Decided 2026-10-24. | Each extra format adds a converter and its failure cases. | Also DOCX, MOBI, AZW. Rejected for release 1: three more converters. | Other types are rejected with a reason. |
| 5 | product | Risk tier is high bar. Decided 2026-10-24. | The app parses untrusted files and holds private libraries. | Reversible. Rejected: a malformed file can attack the converter. | 50 MB limit, type check by content, sandboxed conversion with a timeout, owner-only libraries. |
| 6 | product | Release 1 scope: upload, library list, browser reading, upload status, one account per reader. Decided 2026-10-24. | This is the smallest set that can move the metric. | Collections, search, position sync, retry queue, shared libraries. Rejected: none of them moves the metric. | The cut items wait for release 2. |
| 7 | product | The app is vendor-neutral, with no e-reader brand in its name, code or docs. Decided 2026-10-24. | The repo can go public later. A brand name invites a trademark claim. | A brand-named app. Rejected: it limits sharing and implies a vendor link. | The brief quotes the neutral goal that the owner chose. |
| 8 | product | One reader has one book per file. A second upload of the same bytes is rejected with a link to the book. Decided 2026-10-26. | **Q1, S4 AC6, AC8.** Two rows with one file waste space and confuse the list. The sha256 of the bytes names the content. A file name does not. | Keep both. Rejected: two equal rows. Replace. Rejected: it can remove a book the reader is reading. | A unique key on (reader, sha256). Two readers with one file each get a book. |
| 9 | product | Release 1 has book delete and account delete. Each delete removes the original, the converted file, the cover and the rows. Decided 2026-10-26. | **Q2, S9-S12.** Uploaded files are personal data. A reader must be able to remove them. | Book delete only. Rejected: an account with files stays forever. No delete. Rejected: the brief tier is high bar for personal data. | S9 to S12 join release 1. The brief scope gains delete. |
| 10 | product | Each reader has a storage limit of 1 GB. Over the limit, the upload is rejected with the reason `over_quota`. Decided 2026-10-26. | **Q3, S4 AC9-AC10.** With no limit, one reader can fill the disk with files of 50 MB. | No limit. Rejected: one reader can stop uploads for all readers. | Two parallel uploads must not pass the limit together. |
| 11 | product | A missing title, author or cover gets a fallback: the file name without extension, "Unknown author", a plain cover with the title. Decided 2026-10-26. | **Q4, S5 AC6.** A missing label does not make a book unreadable. A failure loses a good file. | Fail the book. Rejected: it hurts the metric and the reader for no reason. | Every book in the list has a title, an author and a cover. |
| 12 | product | The metric clock runs from `UploadReceived` (the last byte) to `BookReady`. The 95% counts received uploads only. A failed conversion is a miss. Rejects have their own count by reason. Decided 2026-10-26. | **Q5, S6 AC5.** The metric must measure the app, not the reader's network. A reject never reaches the library. | Clock from the first byte. Rejected: a slow network fails the metric. | `upload_received` is written in the same step as event 7. |
| 13 | product | A PDF that needs a password to open is rejected with the reason `password_protected`. A PDF that opens with no password is accepted, even with print or copy limits. Decided 2026-10-26. | **Q6, S4 AC11-AC12.** The app cannot read a file it cannot open. Limits on print or copy do not stop reading. | Reject every encrypted PDF. Rejected: it refuses many readable PDFs. | The type check opens the PDF with an empty password. |
| 14 | product | A late book feeds a metric report only: the daily share of books ready within 2 minutes, and the list of late books. No alert in release 1. Decided 2026-10-26. | **Q7, S6 AC3, AC5.** An alert needs a channel and an owner. The brief cuts email notices. | An alert under 95%. Rejected for release 1: nobody owns it in a 2-week playground. | `BookReadyLate` is derived on read from events 7 and 16. |
| 15 | product | `ConvertBook` renders page 1 in the sandbox before `BookReady`. A book that does not render fails with `unreadable`. A later `BookOpenFailed` keeps the status Ready, shows a message and counts in the report. Decided 2026-10-26. | **Q8, S5 AC8, S8 AC3.** One browser that fails does not prove the book is broken. The render check proves readability once, where the app controls the tool. | Back to failed on `BookOpenFailed`. Rejected: one client changes a fact for all clients. | The metric report shows open failures next to the 95%. |
| 16 | product | A request for another reader's book gets 404, the same answer as a missing book. The app logs `BookAccessDenied`. Decided 2026-10-26. | **Q9, S8 AC2, S9 AC3.** A 403 tells the caller that the id exists (IDOR enumeration). | 403. Rejected: it leaks which ids exist. | Every book query filters by the owner. A miss and a foreign book share one code path. |
| 17 | product | The 1 GB quota counts the original file sizes only. Converted files and covers do not count. Decided 2026-10-26. | **D1, S4 AC9-AC10.** The reader sees and can predict the original sizes. A converted size is known only after conversion. | Count all copies. Rejected: the limit then changes after the upload passed it. | `bytes_used` changes at `UploadReceived` and at delete only. |
| 18 | tech | `DeleteAccount` changes `Account(reader)` only. Sign-in stops at once. Policy P6 removes the library rows, then P4 removes the files, seconds later. Decided 2026-10-26. | **D4, S12 AC1.** Account and Library have different rules. One command changes one aggregate. Nobody can reach the files during the lag. | One transaction for account and book rows. Rejected: it joins two aggregates for no rule. | P6 must survive a crash: step 5 picks its strategy. |
| 19 | tech | Intake runs a sandboxed inspect with a 10 s limit before `UploadReceived`. It checks type, DRM, password and damage. A failure is `UploadRejected(reason)`. Decided 2026-10-27. | **Q17, S4 AC2, AC4, AC11, AC13.** Each of these checks parses an untrusted file. The brief puts all parsing in a sandbox. | Move the checks into `ConvertBook`. Rejected: the reader waits for a failure, and decisions 12 and 13 change. | The upload request waits up to 10 s. The sandbox runs twice per file. |
| 20 | tech | The 50 MiB check runs before the transfer ends. The server rejects a larger Content-Length at once, and stops a stream at 50 MiB + 1 byte. Decided 2026-10-27. | **Q10, S4 AC3, AC14.** A 4 GB request must not fill the disk or hold a worker. | Check after the transfer. Rejected: the server stores 4 GB first. | Uploads stream to a temp file with a byte count. |
| 21 | tech | Conversion timeout 60 s. A book still Processing 5 minutes after `UploadReceived` fails as `stuck`. Decided 2026-10-27. | **Q12, S5 AC4, S7 AC1.** Inspect 10 s plus conversion 60 s fits inside the 2-minute metric with a short queue. 5 minutes is well past any live job. | 120 s timeout. Rejected: one slow file then always misses the metric. | P2 runs every minute, so a stuck book fails within 6 minutes. |
| 22 | tech | Sign-in uses email and password, 12 characters minimum, hashed with Argon2id. The cookie is HttpOnly, Secure, SameSite=Lax. A session ends 14 days after sign-in. Decided 2026-10-27. | **Q13, S1-S3.** It needs no email service in release 1. | Magic link. Rejected: it adds an email provider and its failure cases. | Release 1 has no password reset by email. |
| 23 | tech | The converter writes to `staging/<upload id>/`. `MarkBookReady` moves the output to the book key. When it updates 0 rows, the job removes the staging folder. A daily sweep removes staging folders older than 1 day. Decided 2026-10-27. | **Q15, S6 AC4.** A delete during conversion must leave no file behind. | Write to the book key at once. Rejected: a deleted book leaves an orphan file. | Storage has two areas: staging and books. |
| 24 | tech | `libraries.bytes_used` stores a copy of the sum of `books.size` per reader. Only `Library(reader)` changes it, in the same transaction as the book row. Decided 2026-10-27. | **D1, S4 AC10.** The quota guard is one conditional update on one row. A sum over books needs a lock on all of the reader's rows. | Sum on each upload under a reader lock. Rejected: more code for the same guard. | A test compares `bytes_used` with the sum after upload and delete. |
| 25 | product | Stage is `mvp`. Parsing, personal data and the quota race keep `v1` rigour. Decided 2026-10-27. | The metric tests whether readers want the app, in a 2-week box. The brief tier is high bar for those three parts. | `v1` for all. Rejected: full rigour on every criterion before the metric shows demand. | The build runs in `fast` mode, with guard-removal tests on the high-bar invariants. |
| 26 | tech | `GET /api/sessions/current` answers 200 with the email, or 401. Decided 2026-10-27. | **Plan D1, S2 AC1, S3 AC1-AC2.** The pages need a signed-in check before the library list exists. | `GET /api/books` in PR 1. Rejected: it pulls a PR 2 read forward. | Identity has one read endpoint. |
| 27 | tech | After 10 failed sign-ins for one email in one hour, sign-in answers 429 `too_many_attempts`, also with the right password. Decided 2026-10-27. | **Plan D2, threat model.** 429 is the HTTP answer for a rate limit. The reader sees why sign-in stops. | 401 at the limit. Rejected: it hides the lock. | Parallel guesses can pass 10 by the size of the burst. No lock protects the count. Ten wrong passwords from anyone lock the reader out for 1 hour. |
| 28 | product | After sign-up, the page signs the reader in and shows the library. Decided 2026-10-27. | **Plan D3, S1 AC1.** The reader sees the empty library at once. | Send the reader to the sign-in page. Rejected: one more step for no rule. | The sign-up page calls `POST /api/accounts`, then `POST /api/sessions`. |
| 29 | tech | Sign-up has no rate limit in the `mvp` stage. Decided 2026-10-27. | **Review of PR 1.** S1 AC2 answers 409 for a taken email. A limit per IP needs a client IP that a proxy can pass. | A limit per IP now. Rejected: no proxy exists yet, so the IP rule cannot be correct. | A script can list which emails have accounts. Each sign-up costs one Argon2id hash. Review at `v1`. |
| 30 | product | A failed book keeps its file key. A new upload of the same bytes links to the failed book. Decided 2026-10-28. | **R6, decision 8.** The reader deletes the failed book, then uploads again. The library shows Delete for each status. | A new upload replaces a failed book. Rejected for mvp: it needs a second write path for one rare case. | No code change. The S4 AC6 answer can name a failed book. |
| 31 | product | The event rows of a deleted book or account stay. This narrows "the rows" of decision 9. Decided 2026-10-28. | **D15, D16, decision 12.** The metric report counts each received upload. The rows hold a random id, an event name, a reason and a time only. | Delete the event rows too. Rejected: past days of the report change after a delete. | Personal data goes with the book and account rows and the files. |
| 32 | technical | An upload locks the `accounts` row of its reader until it commits. Decided 2026-10-28. | **D17.** Without the lock, an upload that ends after P6 leaves a book that no step removes. | A daily sweep of books with no account. Rejected: the book stays for up to a day. | Library depends on one Identity table. An account delete waits for an open upload. |
| 33 | technical | A POST, PUT or DELETE whose `Origin` is not `APP_ORIGIN` gets 403 `cross_origin`. Decided 2026-10-28. | SameSite=Lax still sends the cookie from a sibling subdomain. A proxy can rewrite `Host`, so the API cannot compare against it. | SameSite=Lax alone. Rejected: a sibling subdomain can delete an account. Fetch metadata only. Rejected: an older browser sends no header. | Each API deploy sets `APP_ORIGIN`, for example `https://ebookdrop.example`. A request with no `Origin` passes. |
| 34 | technical | The quota CHECK on `libraries` stays a backstop with no test of its own. Decided 2026-10-28. | **R10.** The conditional update is the guard, and S4 AC9 and AC10 test it. | A test that removes the conditional update. Rejected for mvp: it tests the database, not the app. | A broken CHECK shows only when the conditional update also breaks. |
